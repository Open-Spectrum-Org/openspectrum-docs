# Open Spectrum v0.0.2 — Implementation Log

This document records what was actually built in Phases 1, 2, and 3 of the
v0.0.2 refactoring described in `v0.0.2_planning.md` (§34).

All work is in the PWA (`openspectrum-app/pwa/`).

---

## Phase 1 — Data Foundation

**Commit:** `c79549e`
**Date:** 2026-09-09

### Goal (from planning doc §34)

Refactor the data model to support event time vs record time, rich events,
flexible assessments, custom tags, context, raw vs derived data, and focus
areas.

### What was built

#### Dexie schema v2 with migration

`src/db/database.ts` bumped from schema v1 to v2. The upgrade migration runs
for any existing database and fills safe defaults on all existing observations
so no data is lost.

New tables added in v2:

| Table | Purpose |
|---|---|
| `assessment_scales` | Configurable rating systems (numeric or categorical) per event category |
| `observation_assessments` | Per-observation ratings against a scale |
| `focus_areas` | Active investigations a parent is tracking |
| `observation_focus_areas` | Join table linking observations to focus areas |

#### Richer Observation model

`src/types/database.ts` — `Observation` gained the following fields:

| Field | Type | Purpose |
|---|---|---|
| `event_time_precision` | `'exact' \| 'date_only' \| 'approximate' \| 'unknown'` | Signals how reliable the timestamp is |
| `event_end_at` | `string \| null` | End of a duration event |
| `event_timezone` | `string \| null` | Timezone of the event |
| `data_layer` | `'raw' \| 'derived' \| 'ai_interpreted'` | Distinguishes parent observations from computed records |
| `duration_minutes` | `number \| null` | First-class duration (was in JSON blob) |
| `quantity` | `string \| null` | JSON `{value, unit}` (e.g. medication dosage) |
| `severity` | `number \| null` | 1–5 severity (first-class) |
| `confidence` | `number \| null` | 0–1 parent confidence rating |
| `context_data` | `string \| null` | JSON: school day, location, routine, etc. |
| `event_data` | `string \| null` | Replaces `incident_data` — type-specific attributes |

`incident_data` content is copied to `event_data` during migration.

#### Open tag categories

`TagCategory` type changed from a closed enum to an open string with known
system values listed in `SYSTEM_TAG_CATEGORIES`. All 9 system categories are
declared: `behavior`, `food`, `medication`, `emotion`, `sleep`, `sensory`,
`transitions`, `successes`, `trigger`, `other`.

#### New types

```ts
AssessmentScale   — configurable rating system (numeric or categorical)
ObservationAssessment — per-observation rating against a scale
FocusArea         — parent investigation ("Are mornings getting harder?")
ObservationFocusArea — join table
```

#### Seeded data

`src/db/seed.ts` seeds 5 system assessment scales on first run:

| Scale | Type | Range / Options |
|---|---|---|
| Mood | numeric | 1–5 |
| Sleep Quality | numeric | 1–5 |
| Behavior Severity | numeric | 1–5 |
| Food Reaction | categorical | adverse / neutral / positive |
| Medication Effect | categorical | worse / no change / better |

Scales are tagged with `applies_to_categories` so that relevant scales surface
for a given observation's category.

#### New query files

- `src/db/queries/assessments.ts` — CRUD for assessment scales and
  observation assessments
- `src/db/queries/focusAreas.ts` — CRUD for focus areas and their links to
  observations

### Design decisions

- No user-visible Focus Area UI was built in this phase — the data model is
  ready but the feature is deferred to Phase 4.
- `event_time_precision` distinguishes what the parent meant, not what the
  database stores. The `occurred_at` column always holds an ISO timestamp;
  precision tells the UI how to display it.
- `data_layer` ensures raw parent observations are never silently overwritten
  by derived or AI-generated data — a core principle from the planning doc.

## Phase 2 — Capture

**Commit:** `e1adaf2`
**Date:** 2026-09-09

### Goal (from planning doc §34)

Improve mobile-first logging: adaptive ordering, custom tags, assessment,
time offsets, compact capture workflows.

### What was built

#### TimeOffsetPicker (`src/components/TimeOffsetPicker.tsx`)

New bottom sheet that lets parents log events in the past without entering
an exact timestamp. Options:

| Label | Offset | Precision set |
|---|---|---|
| Now | 0 min | `exact` |
| 30 min ago | −30 min | `approximate` |
| 1 hr ago | −60 min | `approximate` |
| 2 hrs ago | −120 min | `approximate` |
| Earlier today | start of day | `date_only` |
| Yesterday | yesterday noon | `date_only` |
| Custom | manual picker | `approximate` |

The selected offset and precision are passed to `insertQuickTapObservation`
via the new `options` parameter (`occurredAt`, `precision`).

#### QuickTagGrid — all 9 categories (`src/components/QuickTagGrid.tsx`)

Previously showed only the core 4 categories. Updated to expose all 9 system
tag categories in two visual groups:

- **Core 4**: behavior, emotion, food, medication (shown first)
- **Separator**
- **Remaining 5**: sleep, sensory, transitions, successes, trigger, other
  (sorted alphabetically)

Tags within each category are sorted by usage count (descending), so
frequently tapped tags rise to the top.

#### Adaptive tag ordering (`src/utils/tagUsage.ts`)

Usage counts stored in `localStorage` keyed by tag ID. Every tap increments
the count. `QuickTagGrid` reads these counts at render time and sorts
accordingly. The ordering adapts gradually — it does not rearrange on every
tap (count must change meaningfully before visual order shifts).

#### CreateTagSheet (`src/components/CreateTagSheet.tsx`)

New bottom sheet letting parents define custom tags:

- Category picker (all 9 system categories)
- Tag name input
- Optional color picker (6 preset swatches)
- Saves via `insertCustomTag` in `src/db/queries/tags.ts`

Custom tags are stored in `tag_definitions` with `is_system = 0` and
`child_id` set to the current child. They appear in `QuickTagGrid` alongside
system tags within their category.

#### AssessmentSheet (`src/components/AssessmentSheet.tsx`)

New bottom sheet for rating an observation after it is logged. Triggered by a
"Rate ›" action button in the post-log Toast.

- Loads assessment scales for the observation's category via
  `getScalesForCategory`
- For numeric scales: renders a 1–N button row
- For categorical scales: renders option buttons
- Saves via `insertObservationAssessment`

The Toast was updated (`src/components/Toast.tsx`) to support an optional
action button alongside the undo action, used to surface "Rate ›" after a
quick tap.

#### `useToast` hook updates (`src/hooks/useToast.ts`)

Extended to support `actionLabel` / `onAction` alongside the existing
`undoAction`, allowing the Toast to carry two independent callbacks.

#### `useTags` hook updates (`src/hooks/useTags.ts`)

Now loads tags for all 9 categories rather than 4.

#### Home page wiring (`src/pages/Home.tsx`)

`TimeOffsetPicker`, `CreateTagSheet`, and `AssessmentSheet` wired into the
capture flow. After a successful quick-tap:

1. Toast appears with "Rate ›" button (if scales exist for the category)
2. Parent can optionally open AssessmentSheet to rate
3. Rating is saved as an `ObservationAssessment` linked to the observation

### Design decisions

- Assessment is always optional and post-hoc — it does not interrupt the
  primary logging flow.
- Usage counts live in `localStorage` (not IndexedDB) to avoid adding a new
  table for a lightweight preference. This means counts do not sync across
  devices, which is acceptable for Phase 2.
- Custom tags are per-child, not per-family, matching the data model's
  `child_id` field on `tag_definitions`.

## Phase 3 — Timeline / Review

**Commit:** `82221b3`
**Date:** 2026-09-09

### Goal (from planning doc §34)

Build a dense timeline, date grouping, filters, and compact summaries.

### What was built

#### Week view with compact rows

`src/pages/Timeline.tsx` gained a `viewMode: 'day' | 'week'` state. A
Day | Week toggle sits above the filter row.

In week mode:
- The last 7 days ending on the current `date` are shown, newest first.
- Each day has a date header (`Today`, `Yesterday`, `Mon Sep 8`).
- Days with no observations show a "Nothing logged" line.
- Tapping any row switches to day view on that date.
- The DateNavigator jumps ±7 days instead of ±1.

#### useWeekObservations hook (`src/hooks/useWeekObservations.ts`)

New hook that loads 7 days of observations in a single query:

```ts
useWeekObservations(endDate: string): {
  days: DayData[];   // newest first
  loading: boolean;
}
```

Internally calls `getObservationsByDateRange`, which bulk-loads tags and
assessments for all observations in the range in two round-trips (no N+1).

#### TimelineRow component (`src/components/TimelineRow.tsx`)

Compact single-line entry used in week view:

```
● 09:15  behavior · Meltdown  [★ 3/5]
```

- Coloured dot (category colour)
- Time — respects `event_time_precision`:
  - `date_only` → `Earlier`
  - `approximate` → `~09:15`
  - `exact` / `unknown` → `09:15`
- `category · title`
- Optional assessment badge on right

#### Assessment badges on TimelineCard

`src/components/TimelineCard.tsx` now renders assessment badges below the
title if the observation has ratings:

- Numeric: `{scale.name} {value}/{max}` in a blue pill
- Categorical: `{scale.name}: {value}` in a grey pill

The same `displayTime` precision helper is applied to the card's timestamp.

#### Dynamic category filter row

`src/components/DaySummaryRow.tsx` was refactored from a hardcoded 4-category
display to a dynamic list:

```ts
interface DaySummaryRowProps {
  categories: Array<{ key: string; count: number; color: string }>;
  activeCategories?: Set<string>;
  onToggle?: (category: string) => void;
}
```

`Timeline.tsx` computes `allCategories` from the actual observations in view
(day or week), sorted by count descending. Only categories with logged entries
appear. The filter row scrolls horizontally if many categories are present.

The now-redundant `getDaySummary` query call was removed from `useObservations`.
The `getDaySummary` function is kept in `observations.ts` for use by future
reports.

#### Bulk assessment loading

`src/db/queries/assessments.ts` gained `getAssessmentsForObservations(ids)`,
which loads all assessments for a list of observation IDs in a single
`anyOf` index scan followed by a `bulkGet` for the scales:

```ts
getAssessmentsForObservations(ids: string[]): Promise<Record<string, AssessmentWithScale[]>>
```

`getObservationsByDate` and `getObservationsByDateRange` both use a shared
`attachTagsAndAssessments` helper that bulk-loads tags and assessments in two
parallel round-trips rather than one per observation.

#### New types

```ts
AssessmentWithScale   // ObservationAssessment + resolved AssessmentScale
ObservationWithTags   // extended: assessments?: AssessmentWithScale[]
```

`assessments` is optional and backwards-compatible — existing callers that
don't use it are unaffected.

### Design decisions

- The week query loads all 7 days in one `getObservationsByDateRange` call,
  grouping by date in JavaScript. This is simpler than 7 parallel
  `getObservationsByDate` calls and avoids 7× the round-trips.
- Assessment data is attached at the query layer (not the component layer) so
  both day and week views get it for free with no extra calls.
- The `DaySummaryRow` refactor is backwards-compatible in spirit — callers
  just pass a different prop shape. The `DaySummary` type is kept in
  `database.ts` because it may still be used by reports.

## Phase 4 — Focus Areas

**Commit:** `d23af60`
**Date:** 2026-09-09

### Goal (from planning doc §34)

Let parents create named Focus Areas ("Why do mornings go wrong?"), associate
relevant observations, and filter the timeline by focus.

### What was built

#### FocusAreas page (`src/pages/FocusAreas.tsx`)

New page accessible via the 🎯 tab in the NavBar (replacing the Insights tab,
which remains reachable at `/insights`).

- Three sections: Active / Paused / Completed
- Each `FocusAreaCard` shows: status dot, title, description, associated
  category chips, up to 5 guiding questions, and a "X obs in last 30 days"
  count computed from `related_categories`
- "View in Timeline →" button navigates to `/timeline` with the focus area
  ID passed as router state, pre-activating the focus filter

#### FocusAreaSheet (`src/components/FocusAreaSheet.tsx`)

Create / edit bottom sheet:

- Title input, description textarea
- 9-category multi-select (chip toggles) — stores as JSON in `related_categories`
- Up to 5 free-text guiding questions — stored as JSON in `questions`
- Status picker (Paused / Active / Completed) — edit mode only
- Delete button — soft-delete via `changeStatus(id, 'completed')` pattern;
  full remove available

#### useFocusAreas hook (`src/hooks/useFocusAreas.ts`)

New hook with full CRUD surface:

```ts
useFocusAreas(): {
  areas: FocusArea[];         // sorted: active → paused → completed
  loading: boolean;
  refresh(): Promise<void>;
  create(title, description, relatedCategories, questions): Promise<void>;
  update(id, title, description, relatedCategories, questions, status): Promise<void>;
  changeStatus(id, status): Promise<void>;
  remove(id): Promise<void>;
}
```

#### updateFocusArea query (`src/db/queries/focusAreas.ts`)

Added `updateFocusArea(id, fields)` — partial update using Dexie's `update()`.

#### Lightweight observation count query

`getObservationCategoryCountsByDateRange(childId, startDate, endDate)` added
to `src/db/queries/observations.ts`. Returns `Record<string, number>` (category
→ count) without loading tags or assessments. Used by `FocusAreas.tsx` to show
"X obs in 30 days" per focus area without N+1 joins.

#### Timeline focus filter (`src/pages/Timeline.tsx`)

- Reads initial focus area from `useLocation().state.focusAreaId` (set by
  "View in Timeline →" from the Focus Areas page)
- Shows active focus areas as 🎯 chip row above the category filter row
- Selecting a chip filters observations to matching `related_categories`;
  deselecting clears the filter
- Switching focus areas clears the category filter to avoid confusing
  compound filters

### Design decisions

- The NavBar has 5 slots (Home, Timeline, Focus, Insights, Profile). Insights
  was removed from the NavBar to give Focus its own tab — `/insights` still
  works as a route for direct access.
- Focus Areas use `related_categories` (JSON string) rather than a separate
  join table because the number of categories is small (≤ 9) and a join table
  would require a new Dexie migration. No schema change was needed for Phase 4.
- The 30-day observation count on the Focus Areas page uses a lightweight query
  that skips tag/assessment joins. Exact per-observation linking (via
  `observation_focus_areas`) is reserved for a later phase when the parent
  explicitly associates individual observations with a focus area.

## Phase 5 — Intelligence

**Commit:** `6c2d9c8`
**Date:** 2026-09-09

### Goal (from planning doc §34)

Add baselines, trend detection, period comparisons, contextual prompting,
hypothesis generation, and assessment score reporting to the Insights page.
Show time-aware prompts on the Home page.

### What was built

#### Rules engine (`src/utils/insights.ts`)

New pure module — no DB calls, no React imports. Accepts plain data objects
and returns human-readable text:

**`generateHypotheses(data: HypothesisInput): Hypothesis[]`**

Eight rules, returning up to 5 results. Every rule is guarded against sparse
data to avoid misleading outputs:

| Rule ID | Trigger | Example text |
|---|---|---|
| `activity-spike` | Current period ≥ 30% more than prior | "Logging activity is up 45% compared to the previous period." |
| `activity-drop` | Current period ≤ 30% less than prior | "Fewer observations this period (38% fewer)." |
| `difficult-day-load` | Difficult days have ≥ 40% more obs than typical | "Difficult days have 62% more logged events than typical days." |
| `morning-peak` | Morning count > 1.5× afternoon and evening | "Most observations occur in the morning hours." |
| `evening-peak` | Evening count > 1.5× morning and 1.2× afternoon | "Evening hours show the highest activity." |
| `weekend-spike` | Weekend avg > 1.5× weekday avg | "Weekends have significantly more observations on average." |
| `weekday-spike` | Weekday avg > 1.5× weekend avg | "Weekdays show higher observation counts than weekends." |
| `success-gap` | ≥ 5 behavior events and successes < 25% of behaviors | "Behavior events (12) outnumber successes (1) by a wide margin." |
| `trigger-behavior` | Both trigger and behavior appear in top tags | "Both triggers and behavior events appear frequently." |
| `sleep-gaps` | Sleep < 0.3 logs/day despite ≥ 5 total obs | "Sleep has not been logged frequently this period." |
| `assessment-*` | Numeric scale with ≥ 5 ratings | "Average Behavior Severity is 3.4/5 (moderate) based on 8 ratings." |

**`generateContextualPrompts(params): ContextualPrompt[]`**

Returns 1–2 prompts for the Home page based on:

- Time of day: morning (6–10h), midday (10–14h), evening (16–20h), night (20–6h)
- `hasReflectionToday`: if evening and no reflection, nudges toward timeline rating
- `recentMeltdownCount`: if ≥ 2 recent difficult behavior events, suggests context logging
- `topCategory`: evening nudge to reflect if a dominant category is being tracked

#### New report queries (`src/db/queries/reports.ts`)

**`getAssessmentAverages(childId, startDate, endDate): Promise<AssessmentAverage[]>`**

Joins observations → `observation_assessments` (via `anyOf` index scan) →
`assessment_scales` (via `bulkGet`). Returns per-scale averages (numeric) and
value distributions (categorical), sorted by usage count descending.

```ts
interface AssessmentAverage {
  scaleId: string;
  scaleName: string;
  scaleType: 'numeric' | 'categorical';
  avg: number | null;       // null for categorical scales
  maxValue: number | null;
  count: number;
  distribution: Record<string, number>;  // categorical value → count
}
```

**`getDayOfWeekPattern(childId, startDate, endDate): Promise<DayOfWeekCount[]>`**

Always returns 7 entries (Sunday → Saturday), including days with 0
observations. Used for the day-of-week bar chart.

#### useInsightsData hook — extended (`src/hooks/useInsightsData.ts`)

Hook signature updated to `useInsightsData(startDate, endDate, periodDays)`.
Now fires 9 parallel queries (was 6), adding:

- `priorCategoryBreakdown` — same period shifted back by `periodDays`
- `assessmentAverages`
- `dayOfWeekPattern`

`periodDays` is used to compute `priorStart = addDays(startDate, -periodDays)`
and `priorEnd = addDays(startDate, -1)`.

#### useContextualPrompts hook (`src/hooks/useContextualPrompts.ts`)

Thin wrapper around `generateContextualPrompts`. Runs synchronously in
`useMemo` — no DB calls, no loading state. Exposes a `dismiss` callback that
hides the card for the current session.

```ts
useContextualPrompts(topCategory: string | null, hasReflectionToday: boolean)
  → { prompts: ContextualPrompt[], dismiss: () => void }
```

#### PromptsCard component (`src/components/PromptsCard.tsx`)

Dismissible card shown on the Home page below `ChildSelector`. Returns `null`
when `prompts` is empty (i.e. no prompt applies to the current hour).

#### Insights page — Phase 5 additions (`src/pages/Insights.tsx`)

The `useInsightsData` call was updated to pass `periodDays`. New UI sections:

- **Period comparison badge** — appears on the "Total Logs" summary card when
  prior-period data is available: `▲ 12% vs prior` / `▼ 8% vs prior`
- **Category breakdown** — replaces the single "Most Tracked" insight card
  with a full list; each row shows a trend indicator (`↑45%` / `↓12%`) when
  the change vs the prior period is ≥ 10%
- **Patterns & Insights** — renders hypothesis cards from `generateHypotheses`,
  each with an icon and one to two sentences of plain language
- **Day of Week chart** — horizontal bar chart below the hourly distribution
- **Assessment Averages** — per-scale cards with a progress bar (numeric) or
  pill distribution (categorical)

### Design decisions

- `insights.ts` is intentionally pure (no imports from React or Dexie). This
  means it can be unit-tested without a DOM and reused if a native app is
  added later.
- Hypotheses are capped at 5 to avoid overwhelming parents. Rules run in
  priority order; the cap is applied with `.slice(0, 5)` at the end.
- `recentMeltdownCount` is hard-coded to `0` in the initial `useContextualPrompts`
  call from `Home.tsx`. A future phase can wire this from a lightweight
  query (e.g. behavior observations in the last 48 h).
- `topCategory` is similarly passed as `null` for now. The Home page does not
  currently load observation data; wiring a real value would require a DB call
  on every home-page render. Deferred to a later phase.
- Assessment averages show all scales with data, sorted by usage. Parents
  using custom scales will see them here automatically.

## Phase 6 — Export

**Commit:** `b6af937`
**Date:** 2026-09-09

### Goal (from planning doc §34)

CSV, JSON, date-range export, Focus Area export, multi-Focus export,
raw/derived/AI distinction.

### What was built

#### exportData.ts (`src/utils/exportData.ts`) — new pure module

No React, no Dexie. Accepts plain data objects; returns strings or
triggers a browser download.

**`ExportMetadata` interface**

Carries child name, date range, selected focus areas, total count, and a
`dataLayerNote` constant that explains the three data layers.

**`buildCSV(obs, meta): string`**

Produces a comment-preamble + flat CSV:

```
# OpenSpectrum Export
# Child: Emma
# Date range: 2026-08-11 to 2026-09-09
# Generated: 2026-09-09T14:32:00.000Z
# Data layers: raw = directly logged; derived = system-inferred; ai_interpreted = AI transcription
# Total observations: 42

id,occurred_at,event_time_precision,category,title,notes,tags,duration_minutes,severity,confidence,assessments,data_layer,entry_type
```

- `tags`: pipe-separated names (`Meltdown | School`), avoiding CSV comma
  conflict
- `assessments`: semicolon-separated (`Behavior Severity: 3/5; Mood: 4/5`)
- Internal `csvEscape` wraps fields containing comma, newline, or double-quote
  per RFC 4180

**`buildJSON(obs, meta): string`**

Structured envelope:

```json
{
  "export_metadata": { "generated_at": "...", "child_name": "...",
    "date_range": {}, "focus_areas": [], "total_observations": 42,
    "data_layer_note": "..." },
  "observations": [
    { "id": "...", "occurred_at": "...", "event_time_precision": "exact",
      "category": "behavior", "title": "Meltdown",
      "data_layer": "raw", "entry_type": "quick_tap",
      "tags": ["Meltdown", "School"],
      "assessments": [{ "scale": "Behavior Severity", "scale_type": "numeric",
                        "value": 3, "max": 5 }] }
  ]
}
```

**`triggerDownload(content, filename, mimeType)`**

Three-tier fallback:

1. Blob + `<a download>` — works on desktop and Android Chrome
2. `navigator.share({ files: [file] })` — iOS PWA fallback (guarded with
   `canShare`)
3. `navigator.clipboard.writeText` — last resort; returns `'clipboard'` so
   the UI can show a "paste into a file" message

Return type: `Promise<'download' | 'share' | 'clipboard'>`

**`filterByFocusAreas(obs, areas, selectedIds)`**

- `selectedIds` empty → returns all obs unchanged
- Otherwise: takes the union of `related_categories` for all selected areas
  and keeps only obs whose `category` is in that set
- Handles `null` / malformed JSON with `try/catch` returning `[]`

**`buildFilename(childName, start, end, fmt)`**

Sanitises child name (`[^a-zA-Z0-9_-] → '_'`) and produces
`OpenSpectrum_{name}_{start}_{end}.{fmt}`.

#### Settings page (`src/pages/Settings.tsx`) — replaced

"Coming Soon" placeholder replaced with a full Export Data UI.

**State**

| State | Initial | Purpose |
|---|---|---|
| `preset` | `'30'` | Active date preset |
| `customStart / customEnd` | `''` | ISO dates for custom preset |
| `selectedAreaIds` | `[]` | Selected focus area IDs (multi-select) |
| `previewCount` | `null` | Live observation count (null = not yet loaded) |
| `previewLoading` | `false` | Spinner state for preview |
| `exporting` | `false` | Button loading state during download |
| `exportFeedback` | `null` | Post-export message (success or error) |

**Date computation (useMemo, not state)**

`startDate` and `endDate` are derived from `preset` and the custom inputs.
`preset === 'all'` sets `startDate = '2000-01-01'`.

**Validation (derived)**

`dateError` is set when custom end < custom start. `canExport` requires:
no error, non-zero preview count, non-null child, not currently exporting.

**Live preview effect**

`useEffect` watches `child?.id`, `startDate`, `endDate`,
`selectedAreaIds`, and `areas`. On every change it fires
`getObservationsByDateRange` + `filterByFocusAreas` and updates
`previewCount`. Uses a `cancelled` flag to discard stale results.

**`handleExport(format)`**

Loads the same observations used for the preview, builds the metadata
object, serialises via `buildCSV` / `buildJSON`, calls `triggerDownload`,
and sets the feedback string based on the return value.

**UI sections**

1. `AppHeader` (showHome=true, editable=false)
2. "Export Data" heading
3. Date range — preset pills + optional custom date inputs + error message
4. Scope — "All observations" chip + one chip per focus area (multi-select;
   selecting any area deselects "All observations")
5. Preview row (border box) — count or spinner
6. "No observations in this range" note when count = 0
7. Export CSV (primary) and Export JSON (outline) buttons side by side;
   spinner replaces label while exporting
8. Feedback line — green for success, red for failure; clipboard fallback
   explains what to do

### Design decisions

- `exportData.ts` is intentionally pure (no React, no Dexie) so it can be
  tested without a DOM and is trivially portable to any future native client.
- `filterByFocusAreas` with an empty `selectedIds` returns all observations
  unchanged — the "All observations" chip is purely a UI affordance; no
  filtering occurs.
- The three-tier download approach follows PWA best practice: blob download
  covers desktop and Android; `navigator.share` handles iOS Safari PWA where
  blob downloads are silently ignored; clipboard is the universal fallback.
- No new routes, no NavBar changes, no Dexie migrations were needed.

## What remains (deferred to Phase 7+)

These items were identified during Phase 5 and 6 but are out of scope for
the current sprint.

### High priority — Home page intelligence gaps

- **Real `topCategory` on Home** — `useContextualPrompts(null, false)` in
  `Home.tsx` passes a hard-coded `null`. A lightweight
  `getObservationsByDateRange` (last 7 days) + `getCategoryBreakdown` call
  on mount would supply the real value without a persistent subscription.

- **Real `recentMeltdownCount` on Home** — hard-coded to `0`. Should count
  behavior observations in the last 48 h (or observations where `title`
  contains relevant keywords) and pass the count to `useContextualPrompts`
  so the follow-up nudge fires when ≥ 2 difficult events have occurred.

### Medium priority — Focus Area depth

- **Explicit observation → Focus Area linking UI** — the
  `observation_focus_areas` join table was seeded in Phase 1 but no UI
  surfaces it. Required for "View observations in this Focus Area" and
  focus-specific reports. Entry points: a "Link to focus area" action on
  `TimelineCard`, or an observation detail sheet.

- **Focus-specific reports** — Insights / Reports views scoped to a single
  Focus Area's categories and date range. Would re-use `useInsightsData` with
  a category pre-filter and a narrower date range.

### Low priority / future phases

- **Multi-child support** — `ChildSelector` exists; `ChildProvider` tracks
  an active child. Nothing prevents adding a second child, but the UX for
  switching is minimal. A proper multi-child switcher (avatar row, quick
  switch on long-press) is deferred.

- **Sync / cloud backup** — all data is local-only (IndexedDB). The schema
  has `sync_status`, `last_synced_at`, and `device_id` columns ready for a
  future sync layer. No backend exists yet.

- **Community / Ecosystem** — hypothesis marketplace, peer pattern sharing,
  clinician export formats. Depends on sync layer existing first.
